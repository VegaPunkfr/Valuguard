## 1. PHILOSOPHIE GLOBALE

Ghost Tax est un service d'intelligence financiere IT externe. Il detecte l'exposition cachee dans les depenses SaaS, Cloud et IA d'une entreprise — sans acces systeme, en 48h, pour 490 EUR (590 EUR DACH).

**Pourquoi on contacte :**
Chaque prospect a ete analyse via signaux publics AVANT le premier contact. Le message n'est pas un pitch generique — c'est une preuve de competence. On montre au prospect quelque chose de specifique sur SON entreprise qu'il ne savait probablement pas.

**Promesse de valeur par message :**
- M1 : "On a trouve quelque chose sur votre entreprise"
- M2 : "Ce que ca vous coute chaque jour de ne pas agir"
- M3 : "Comment vous vous situez par rapport a vos pairs"
- M4 : "Votre exposition a augmente depuis notre dernier message"
- M5 : "Derniere opportunite avant expiration des donnees"

**Regle d'or :**
Chaque message doit referencer un signal REEL detecte. Si on peut remplacer le nom de l'entreprise et que le message fonctionne encore — il est trop generique et doit etre reecrit.

## 5. STRUCTURE DES SEQUENCES

### M1 — Premier Contact (Jour 0)

| Element | Detail |
|---------|--------|
| **Objectif psychologique** | Creer un moment "comment elle sait ca ?" |
| **Longueur** | Email: 180 mots max. LinkedIn: 120 mots max |
| **Angle** | Finding le plus choquant/specifique en premiere ligne |
| **CTA** | Lien direct vers ghost-tax.com/checkout |
| **Personnalisation obligatoire** | Nom du prospect, nom de l'entreprise, 2-3 findings specifiques, fourchette EUR |
| **INTERDIT** | "I hope this finds you well", "Our platform", "Book a call", "innovative", mentionner Ghost Tax avant les findings du prospect |

### M3 — Follow-up Cout d'Inaction (Jour +3)

| Element | Detail |
|---------|--------|
| **Objectif psychologique** | Rendre le cout de l'inaction visceral |
| **Longueur** | Email: 100 mots max. LinkedIn: 80 mots max |
| **Angle** | "{X} EUR perdus depuis mon dernier message" |
| **CTA** | Meme lien checkout |
| **Personnalisation obligatoire** | Cout cumule depuis M1 (dailyLoss x 3 jours), rappel du finding principal |
| **INTERDIT** | Repeter les memes findings que M1, "just checking in", "following up" |

### M4 — Re-angle Benchmark (Jour +7)

| Element | Detail |
|---------|--------|
| **Objectif psychologique** | Comparaison aux pairs — pression sociale professionnelle |
| **Longueur** | Email: 150 mots max |
| **Angle** | "Comment [entreprise] se compare a [X] entreprises similaires" |
| **CTA** | Lien checkout |
| **Personnalisation obligatoire** | Benchmark sectoriel (si sample >= 10), percentile, comparaison pair |
| **INTERDIT** | Repeter M1 ou M3, utiliser un benchmark avec confidence < indicative |

### M5 — Rupture (Jour +14)

| Element | Detail |
|---------|--------|
| **Objectif psychologique** | Respectueux mais final. Laisser la porte ouverte sans pression |
| **Longueur** | 60 mots max |
| **Angle** | "Dernier message. Lien vers scan gratuit en cadeau de depart" |
| **CTA** | Lien vers /intel (scan gratuit) — PAS le checkout |
| **Personnalisation obligatoire** | Nom de l'entreprise, recap de l'exposition estimee |
| **INTERDIT** | Tout ton agressif, urgence artificielle, "derniere chance" melodramatique |

## 9. REGLES ANTI-SPAM & DELIVRABILITE

### Configuration email
- **From:** `audits@ghost-tax.com`
- **Reply-to:** `audits@ghost-tax.com`
- **Provider:** Resend (EU region, eu-west-1)
- **Domaine:** ghost-tax.com (SPF + DKIM + DMARC configures)
- **DMARC policy:** quarantine, pct=100

### Rate limiting
| Limite | Valeur |
|--------|--------|
| Par IP par heure | 50 emails |
| Total par jour | 200 emails |
| Par domaine par batch | 5 emails |
| Par batch total | 100 emails |
| Timeout entre envois | Aucun (envoi direct) |

### Regles de contenu anti-spam
- **Plain text prefere** pour les sniper emails (delivrabilite maximale)
- **HTML autorise** pour les drip sequences (avec tracking pixel)
- **Pas de pieces jointes** dans les cold emails
- **1 seul lien** par email (ghost-tax.com/checkout ou /intel)
- **Unsubscribe** obligatoire dans chaque email (token base64url)

## 10. LOGIQUE DE REPONSE

### Machine d'etat prospect

```
discovered → reviewed → shortlisted → contacted → replied → nurturing → qualified → closed
                 ↓           ↓             ↓                     ↓
            suppressed   deferred      suppressed            deferred
```

### Transitions declenchees par action

| Action | Transition |
|--------|------------|
| Prospect identifie dans Apollo | → discovered |
| Operateur review le prospect | discovered → reviewed |
| Prospect passe les seuils de scoring | reviewed → shortlisted |
| Email envoye | shortlisted → contacted |
| Prospect repond (positif ou negatif) | contacted → replied |
| Dialogue engage, pas encore converti | replied → nurturing |
| Prospect dit "pas maintenant" | → deferred (avec revisit_after) |
| Prospect dit "ne me contactez plus" | → suppressed (terminal) |
| Prospect achete Rail A | → qualified |
| Deal ferme (paye + livre) | → closed |

### Que faire quand le prospect repond

| Type de reponse | Action |
|----------------|--------|
| "Interessant, envoyez plus de details" | Repondre dans l'heure. Proposer le rapport complet. Transition → replied |
| "Comment faites-vous sans acces ?" | Repondre avec 3 phrases sur la methode (OSINT, signaux publics). Pas de pave. |
| "Pas interesse" | "Merci pour le retour. Qu'est-ce qui aurait rendu cette analyse plus utile ?" Transition → suppressed |
| "Pas maintenant" | "Compris. Je reviens dans [30/60] jours." Transition → deferred avec revisit_after |
| "Retirez-moi de votre liste" | Retirer immediatement. Transition → suppressed |
| Transfert a un CIO/autre | Repondre au nouveau contact. Proposer un scan dedie. |
| Achat Stripe | Livrer le rapport en priorite. Transition → qualified |

| Signal | Seuil | Action |
|--------|-------|--------|
| 0 ouverture sur 10 emails | Apres 10 envois | Verifier delivrabilite (SPF/DKIM) |
| 0 reponse sur 20 emails | Apres 2 waves | Revoir les findings — trop generiques ? |
