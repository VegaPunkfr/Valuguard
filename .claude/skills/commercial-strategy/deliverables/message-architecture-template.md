# Message Architecture Template — Framework by Role, Channel, and Stage

## Core Positioning Statement

```
For [TARGET BUYER ROLE] at [COMPANY TYPE]
who [PROBLEM/NEED they experience],
[PRODUCT NAME] is a [CATEGORY]
that [KEY DIFFERENTIATOR].
Unlike [ALTERNATIVE/COMPETITOR],
we [UNIQUE MECHANISM].
```

**Ghost Tax example**:
```
For CFOs at mid-market companies (200-2000 employees)
who lack visibility into external IT cost exposure,
Ghost Tax is a decision intelligence service
that delivers actionable IT spend analysis in 48 hours with zero system access.
Unlike traditional IT audits or FinOps platforms,
we analyze from the outside — the same view an acquirer or auditor would have.
```

## Message Matrix by Channel

### Cold Email
```
Subject line formula: [SPECIFIC DATA POINT] + [RELEVANCE TO THEIR COMPANY]
  Example: "[COMPANY] IT exposure: what an external audit would find"
  Anti-example: "Save money on SaaS! Try our free tool"

Opening line: [OBSERVATION about their company, not about you]
  Example: "Your public footprint shows 40+ SaaS tools — typical for [INDUSTRY] at your scale."
  Anti-example: "Hi, I'm [NAME] from Ghost Tax, we help companies..."

Value statement: [ONE sentence — what they get, how fast, what it costs]
Body: [MAX 4 sentences total including opening]
CTA: [ONE clear action, low commitment]
  Example: "Want to see what the scan finds? Takes 90 seconds: [LINK]"
  Anti-example: "Let me know if you'd like to schedule a call to discuss"

Signature: [Name, title, company. No quotes, no banners, no 10-line disclaimers]
```

### LinkedIn (Organic Posts)
```
Hook: [First line must create curiosity or pattern interrupt — max 15 words]
Body structure: Problem → Insight → Implication → (optional) CTA
Length: [80-150 words for engagement, 200-300 for authority]
Tone: [Conversational expert, not corporate. First person. Specific examples.]
Hashtags: [Max 3, relevant, not generic]
```

### LinkedIn (Direct Message)
```
Trigger: [What prompted the message — connection accepted, they engaged with your content, etc.]
Length: [Max 3 sentences]
Tone: [Human, not salesy. Reference specific shared context.]
CTA: [Question, not pitch]
  Example: "Curious — how are you handling SaaS cost visibility at [COMPANY]?"
  Anti-example: "Would love to show you our platform"
```

### Website Copy
```
Headline: [Outcome-first, max 10 words]
Subheadline: [Mechanism or differentiator, max 20 words]
Body: [Short paragraphs, max 3 sentences each. Lead with the reader's world, not yours.]
CTAs: [Action verb + what happens next. Consistent across page.]
Proof elements: [Specific numbers, named sources, verifiable claims]
```

### Follow-Up Emails (Post-Scan, Post-Purchase)
```
Tone: [Helpful expert, not pushy salesperson]
Structure: [Reference previous interaction → New value → Clear next step]
Timing: [Map to drip sequence — see drip-architect skill]
Personalization: [Reference their specific scan results or report findings]
```

## Message Matrix by Funnel Stage

### Awareness (They don't know they have the problem)
- **Goal**: Create problem awareness
- **Tone**: Educational, provocative
- **Content types**: LinkedIn posts, industry reports, benchmark data
- **Key message**: [PLACEHOLDER — e.g., "42% of companies are cutting SaaS budgets, but most can't quantify what they're spending externally."]
- **CTA**: None or very soft (read more, see the data)

### Consideration (They know the problem, exploring solutions)
- **Goal**: Position as the best solution
- **Tone**: Authoritative, evidence-based
- **Content types**: Landing page, methodology explanation, sample report
- **Key message**: [PLACEHOLDER — e.g., "External analysis finds what internal tools miss. 48 hours. Zero system access. Findings guaranteed."]
- **CTA**: Start free scan

### Decision (They're evaluating whether to buy)
- **Goal**: Remove friction, justify the purchase
- **Tone**: Confident, specific
- **Content types**: Pricing page, ROI calculator, proof assets
- **Key message**: [PLACEHOLDER — e.g., "490 EUR. Average finding: 47k EUR. The math works."]
- **CTA**: Purchase / Checkout

### Post-Purchase (They bought, now maximize value)
- **Goal**: Deliver value, create expansion opportunity
- **Tone**: Partner, not vendor
- **Content types**: Report delivery, follow-up insights, Rail B teaser
- **Key message**: [PLACEHOLDER — e.g., "Here's what we found. Here's what it means. Here's what you can do next."]
- **CTA**: Share report internally / Explore deeper analysis

## Voice and Tone Guidelines

### Brand Voice (Constant)
- **Precise**: Use numbers, not adjectives. "47,000 EUR" not "significant."
- **Direct**: State conclusions. Don't hedge with "we believe" or "it seems."
- **Expert**: Write from a position of knowledge, not aspiration.
- **Respectful**: The reader is smart and busy. Don't over-explain.

### Tone Variations (Context-Dependent)

| Context | Tone Adjustment |
|---------|----------------|
| Cold outreach | More conversational, less formal. Earn attention. |
| Landing page | Confident, evidence-heavy. Prove everything. |
| Post-purchase | Warm, partner-like. You're on their side now. |
| Thought leadership | Provocative, insight-driven. Challenge assumptions. |
| Error/bad news | Honest, solution-oriented. No corporate deflection. |

### Language Rules
- Never use: "cutting-edge", "revolutionary", "AI-powered", "best-in-class", "synergy", "leverage"
- Never use: "no obligation", "no commitment", "risk-free" (signals desperation)
- Prefer: Specific over general, active voice over passive, short sentences over long
- Market-specific: Use formal register for DACH (Sie, not du). Use direct register for UK/NL.

## Message Testing Protocol

1. **Before sending any new message at scale**, test with 20-30 recipients first
2. **Track**: Open rate, reply rate, click rate, conversion rate
3. **Minimum sample**: 50 sends before drawing conclusions
4. **Test one variable at a time**: Subject line OR opening line OR CTA, never all three
5. **Winner criteria**: Statistically significant improvement (>20% relative lift)
6. **Update this document** when a new winning message is validated
